# 轻量会话 checkpoint（2026-09-23）

## 产品边界

checkpoint 保存用户认可的会话进度，不保存整个运行时数据库。

- **参与版本根切换**：消息、会话中影响后续决策的元数据、有效上下文/压缩摘要、当前 work 状态、附件绑定。
- **不参与状态恢复**：run、step、part、工具、授权/人工输入、思考摘要、流式事件。这些保留在原审计表，通过执行代数与边界序号筛选；旧授权不能恢复为可执行状态。
- **用量不回滚**：累计消耗继续从实际执行记录计算；当前上下文读数只采用可见步骤。读取采用流式迭代，不再一次装入所有步骤元数据。
- **文件单独选择**：只有明确选择文件回滚才走文件补偿，原有冲突与恢复保护保留。

checkpoint 捕获时才记录“执行代数 → 审计序号上界”的小型版本指针。回滚原子切换消息/必要状态根并推进代数，不扫描或倒放运行事件。新分支不会通过放宽一个全局 cutoff 复活废弃内容。

## 接入

普通新建 Native 根会话默认走轻量模式。`SYNAX_VERSION_HISTORY=legacy` 只影响之后新建的会话，不把已有 v3 会话降级。

旧会话的“升级高性能历史”入口要求停止执行并明确确认：保留当前消息、当前决策状态和附件，但旧 checkpoint 不继续提供回滚；新的 checkpoint 从升级后开始。复制分批进行，最终一次发布可见根；中断可续传，干净失败保留原 v2 内容。旧 undo 日志随后分批回收。超过 1024 条待回放 journal 的旧回滚直接拒绝并提示升级，避免重现原来的同步卡死。

子会话/分支复制仍明确拒绝，不通过复制整段历史伪装成高性能支持。

## 有界读取与资源控制

- 会话窗口：最多 24 条消息，相关执行预览总响应约束为 2 MiB；更早/最新导航**替换**窗口，不累计合并。失效游标回到最新分支。
- 长消息按段读取；截断预览禁止直接编辑，防止覆盖未展示内容。
- 模型历史使用近期消息窗口，并对请求内历史缓存计量；省略历史会给模型明确提示，不修改用户原始消息。
- 前端历史缓存上限 16 MiB，实时预览和已完成流式片段也有上限。
- 保留最近 128 个 checkpoint、2048 条普通运行事件、1024 条流式重放记录。幂等请求不随意淘汰；其记录有配额保护。
- 不可达版本对象以小批次后台回收；文件 GC 有时间片，不能长时间占用文件快照排他租约。
- 数据库页数上限 4 GiB，WAL 写入准入 64 MiB，保留 512 MiB 磁盘余量；每个附件/文件快照目录上限 2 GiB，外部写入限制并发与在途容量。已有超限数据不强制截断，回收仍可执行。
- 用户删除会话先写 tombstone，使会话立即不可见；后台每批至多 64 条记录释放数据，随后由对象/附件回收器释放不可达内容。不执行大事务级联删除或全库 VACUUM。

这些是有界读取和准入保护，不是“任意机器和任意文件规模都能一秒完成”的承诺。实际文件恢复时间取决于 I/O。当前仅做类型检查和少量关键路径定向测试，未替换安装中的应用，也未迁移真实用户数据。
