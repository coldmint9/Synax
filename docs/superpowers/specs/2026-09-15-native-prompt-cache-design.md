# Native 请求前缀稳定性与缓存用量设计

日期：2026-09-15

状态：对话方案已确认；本文待复核，尚未实施。

## 1. 目标、范围与非目标

修复 Synax Native 请求链路中参考块实例 ID 不稳定、动态 Work/计划/goal 数据改变 system 前缀、运行时提醒未随历史回放、Anthropic 缓存边界不足，以及 OpenAI-compatible 缓存统计低报。交付请求级回归、可重复运行的本地诊断脚本和分组报告。

范围包括 Native 请求构造、共享 usage 归一化、hooks、session 统计与 ACP/CLI 旧数据兼容解析。ACP、Codex CLI、Claude Code 的请求构造不重构。

不新增监控页面或数据库表，不改写旧对话记录，不调整压缩阈值、缓存 retention 默认值，不默认设置 OpenAI promptCacheKey 或 24h retention。不承诺缓存提升百分比。本地前缀一致不代表服务端缓存命中。

## 2. 已核对的集成点与工作区约束

- `loop-prompt.ts` 当前将参考块的运行时 `id` 序列化到 system，并在 system 中拼入 Work 数据。
- `synax-mode-prompt.ts` 当前将保存计划与 goal 状态混入模式指令。
- `loop-runtime.ts` 已有末尾 user `<system-reminder>` 通道与最终 token 检查；本次扩展该通道，而不添加尾部 system 消息。
- `loop-model-messages.ts` 按步骤重建 assistant/tool 消息，并处理输入队列和被压缩步骤；提醒回放必须加入这一生命周期。
- `llm-runtime/prompt.ts` 当前合并 system 文本并重建对话消息，不能可靠保留消息级 providerOptions。
- `provider-strategy.ts` 当前以 provider ID 或域名识别 Anthropic 缓存能力。
- hooks 与 session usage 投影各自解析字段，现有空值合并可能让 SDK 零值覆盖 raw 命中量。

保留已有前端样式、会话 UI、路由、生成的 tsbuildinfo，以及 `loop-runtime.ts` / `subagent-orchestrator.ts` 的子代理超时改动。实现前重新检查工作区差异，只修改本功能所需部分。不得改动 node_modules。

## 3. 选择的架构

采用分层增量设计：

1. `usage.ts`：纯函数，负责来源识别、验证、归一化与旧数据兼容；不访问数据库、不记录正文。
2. 确定性上下文投影：只改变模型可见表示，不改变存储身份与引用解析。
3. 请求快照与历史回放：沿用 step metadata，固定已发送提醒与缓存锚点身份。
4. `cache-policy.ts`：按实际适配器能力生成缓存标记，不承担授权和模式判断。
5. `cache-diagnostics.ts`：比较脱敏区块指纹，结合 provider usage 和计时生成报告。

不采用仅增加 fallback / 缓存标记的局部修补，因为它不能稳定历史。不新增完整请求存储系统，以免扩大迁移和敏感内容留存范围。

## 4. Usage 契约

### 4.1 来源与原始证据

在 provider/SDK 边界收集白名单内的原始 usage 字段与字段存在性；禁止把请求正文、响应正文或完整 raw SSE 作为 usage 证据持久化。

新增带版本的归一化信息，包含：

- 来源：协议、适配器以及 SDK / raw / ACP / CLI / legacy 分类。
- input total、output、reasoning、cache read、cache write。
- 各缓存字段的 known / unknown 状态、选中来源及原始字段是否存在。
- input 的计数口径：原始未缓存输入或已包含缓存的总输入。

兼容保留已有 usage 字段；新增消费者以归一化信息为准。重复归一化必须幂等。不同请求的原始 usage 不得通过全局可变状态混用；重试与流式增量记录按请求/尝试关联。流中的 finish-step 与 finish 若报告同一步用量，不重复累计。

### 4.2 字段选择与数值验证

| 情况 | 处理 |
| --- | --- |
| 原始协议标准缓存字段存在且合法，包括 0 | 使用标准字段 |
| 标准字段不存在，兼容协议有已知自定义命中字段 | 使用自定义字段，例如 prompt_cache_hit_tokens |
| SDK 合成 0，但原始兼容字段为正数 | 使用原始字段，不被合成 0 遮蔽 |
| 标准字段存在但非法 | 标记未知，不用自定义字段掩盖非法标准值 |
| 字段缺失、null、字符串、负数、非整数、非有限数 | 标记未知，不强制转成 0 |
| ACP/CLI 来源明确、字段契约明确 | 按该来源解析；显式合法 0 是已知值 |
| 旧记录只有来源不明的 SDK 0 | 缓存统计可用性标为未知 |
| 旧记录有可识别的 raw 字段 | 复用同一优先级，不修改存储记录 |

归一化 input 是包含缓存读取/写入的总输入。原始 Anthropic 未缓存 input 与其 cache read/write 按协议口径合成一次；已由 SDK 或本模块合成的 input 不再次加缓存。原始必需分量缺失时不推测未知分量。缓存写入明细与总数不得重复求和。

原始 OpenAI Chat / Responses 输入总数已经包含缓存读取，不再相加。只有所需分量已知时才计算派生总量；旧数值汇总接口可维持兼容零初值，但必须用新增可用性字段区分未知。

### 4.3 汇总

保留 `usage.self/tree` 和现有 coverage；增量增加 cache write、缓存字段已知/未知样本数、缓存率计算所用的匹配输入分母与匹配 cache read 分子。

缓存率 = 同时已知 cache read 与 input 的样本之 cache read 总和 / 同批样本的 input 总和。分母为 0 或没有有效样本时返回未知，不能将各步骤百分比求平均。已知 cache read 但 input 未知可计入读取总量，不进入缓存率分子或分母。

主会话、子会话和辅助调用分别分组；辅助 usage 不冒充步骤 usage。ACP `usage_update.used` 的上下文占用继续与实际消耗区分，不作为新增计费请求累计。

## 5. 确定性参考数据

模型可见块使用 sourceType/sourceId 等稳定来源信息，不输出 acblk 实例 ID。没有稳定来源时，使用内容指纹作为身份。内容及标题变化仍改变投影；不为了保持指纹而删除有语义的信息。

投影对象显式构建字段顺序，块按稳定来源键、标题和内容指纹排序；相同来源多块以内容指纹区分，不使用实例 ID 做排序兜底。哈希使用固定算法和编码。对正文不做可能改变代码语义的空白归一化。

现有工具定义按 ID 排序继续复用。回归测试验证最终请求中的工具定义，而非增加另一套排序。

## 6. 静态指令与运行时提醒

### 6.1 分层

最终请求顺序：

1. 稳定 system 指令：工作原则、权限、模式规则、参考数据使用规则。
2. 确定性参考数据区：可继续承载在稳定 system 中，但诊断单独分块。
3. 历史消息：原 user、已发送提醒、assistant、tool exchanges。
4. 本步最新运行时 user reminder。

Work 快照、计划执行状态和验收项、goal evidence、步骤号、收敛及失败提醒迁到第 4 层。保存计划、goal 目标和 plan_node 动态数据与模式规则分离。每步只构造一份完整提醒，防止不同帮助函数重复注入。

稳定 system 说明提醒用途及信任边界；XML 标签本身不赋予权限。模式规则保留在 system，实际权限、执行批准、完成验收继续由服务端决定。旧历史、用户文本、工具结果中的“已批准”不能改变真实授权。

### 6.2 快照生命周期

在请求投影、压缩和最终预算检查完成后、首次网络发送前，将本步提醒快照写入对应 step metadata。快照有版本、准确发送文本及内容指纹；保存后不得用后续状态覆盖。

同时保存必要的历史锚点身份和诊断摘要，不持久化整份 prompt。锚点使用所属步骤及内容块的稳定身份，不只依赖易变数组下标。

- 同一实际请求的传输重试复用请求对象与提醒快照，不重新读取动态 Work/计划状态。
- 恢复未完成步骤时，如复用原请求则使用原快照；如果必须改变请求内容，则建立新请求身份，不能宣称是同一快照的重试。
- 恢复已完成步骤按保存文本回放提醒，位置在所属 assistant 响应之前。
- 构造当前请求时不能既从历史回放当前步骤提醒，又在尾部追加一次。
- 旧步骤没有快照则维持现有读取行为，不按当前状态补造历史提醒。
- 排队输入按其实际消费边界持久化并回放；需要时增量保存输入归属信息，不只用可能相同的时间戳推测次序。

一次请求已经发送的对话前缀在下一次保持原有内容与顺序，除非发生明确记录的压缩、合法配置/上下文变化或现有历史清理策略。新 user 输入、上一响应与新提醒仅在相应尾部追加。

### 6.3 压缩、预算与预览

提醒与所属完整步骤一起淘汰，不能留下孤立工具调用/结果或单独长期保留提醒。沿用现有长度限制、压缩策略和高低水位，不为缓存无限保留状态。

预算包括静态 system、参考数据、历史提醒、本步提醒、工具定义与输出预留。记录提醒新增 token 估算；最终请求超限沿用明确的 context_blocked 错误，不截断签名推理以凑预算。

现有 latestSystemPrompt 仍表示静态 system，不误称完整请求。完整请求组成预览另行表示历史和最新状态；不把新增正文复制到诊断日志。

## 7. Provider 元数据与缓存边界

### 7.1 能力配置

连接级缓存能力使用 `options.promptCaching: auto | on | off`，缺省为 auto；通过现有 provider options 配置通道传递并在运行时严格验证，不新增设置页面。此键仅用于网关策略，不透传为供应商请求参数。网关原有 `cacheControl` 请求开关保持兼容。

- 请求显式关闭或连接配置 off：不生成 Anthropic 缓存字段。
- auto：对实际使用原生 Anthropic Messages 适配器的请求启用，不判断 provider 名称或域名。
- on：允许支持 Anthropic Messages 能力的自定义连接启用；不能把不支持的协议强行转换为 Anthropic。
- OpenAI Chat / Responses 不注入 Anthropic 参数，保留 responseOptions 及 store:false 的既有语义。

配置键 promptCaching 的校验与白名单落在现有配置解析链路中；若必须增补用户列举范围以外的配置类型或解析文件，仅做实现该开关必需的修改并加入测试。

### 7.2 无损转换

扩展 system 类型以携带 providerOptions；多个 system 块按原顺序处理，不因简单 join 丢失选项。保留 user/assistant/tool 的消息级和内容级 providerOptions，包括 reasoning signature、encrypted reasoning、工具调用元数据及媒体内容。

转换及缓存策略不得修改调用者对象或签名正文，使用复制后的结构施加合法缓存选项。对于显式禁用或不支持的协议，只剥离 Anthropic 缓存控制字段，不破坏其他 provider 元数据。

### 7.3 锚点与预算

默认 ephemeral。稳定 system 末尾设置边界；历史优先保留上一请求可复用锚点，再选择本请求历史中的合法末尾块作为新边界。最新动态提醒在历史缓存边界之后，不被误选为历史锚点。

统一统计 tools、system、messages 中已有及新增的缓存标记，最终最多四个。优先级：稳定 system、仍匹配的旧历史锚点、本次历史末尾边界、其他合法已有标记。冲突时去除低优先级缓存标记，不删除内容或其他元数据。

不在禁止缓存的 thinking/reasoning 块上设置标记，不移动或改写签名内容；末尾不合法时向前寻找合法块。超过 20 个新增内容块时仍保留旧锚点，不能仅保留最新末尾而失去可复用锚点。旧锚点所属步骤被压缩或内容改变时使其失效，并记录原因。

这些是本次协议回归目标；以项目锁定 SDK 的实际序列化与请求体捕获核验实现，不以中间对象上的标记替代 wire 测试。协议正确不保证服务端达到最小缓存长度或实际命中。

## 8. 诊断与可重复实验

`cache-diagnostics.ts` 提供受控开关。默认持久化数据仅有版本、请求/步骤来源、provider/model/协议、区块指纹和长度、压缩事件及现有计时；不新增完整 prompt、工具结果、密钥或完整响应日志。

在 Native 组装与 provider 适配边界分别测量，按稳定 system、工具定义、参考区、历史和最新提醒分块。比较相邻请求，报告首个变化块与可识别原因。敏感文本只在内存参与指纹计算。

`scripts/diagnose-prompt-cache.ts` 默认使用本地捕获服务或 mocked transport，运行仓库实际组装/网关路径并输出可重复的机器可读结果与文字报告。测试原始捕获可在内存断言，输出报告不含完整正文。

场景包括无参考块、重复 enrich Code Map/Wiki、Work 证据增长、保存计划/获准执行、长 Anthropic 历史、输入队列、压缩与断线恢复。报告包含区块变化、缓存字段覆盖率、匹配输入分母、读取/写入、首 token/总延迟以及可取得的费用。

按 provider/model、主会话/子会话/辅助调用、冷请求/连续步骤/压缩后首请求分组。辅助调用没有可比计时或归属时明确未知，不补零。中断或失败尝试若 provider 未提供 usage，同样不能推算 token 消耗。

真实请求须显式选择，使用既有授权配置，每条可用协议路径做冷请求加连续请求的小样本。无配置/授权时只交付本地验证及操作说明，真实结果标为“未测量”；若配置未启用 caching，报告该事实而非静默覆盖。

## 9. 验收矩阵

| 层级 | 必须覆盖的场景 | 验收依据 |
| --- | --- | --- |
| usage 单元 | 标准 0、raw-only 8000/10000、缺失、非法值、SDK 0 遮蔽 | 归一化数值及 known/unknown 正确 |
| usage 来源 | Chat、Responses、Anthropic raw/SDK、ACP、CLI、旧记录 | 不重复计算，幂等，旧记录不重写 |
| 汇总 | self/tree/aux、混合覆盖率、不均等输入步骤 | hooks 与持久化一致；按匹配样本总量算率 |
| 确定性 | 重生成 ID、enrich 顺序变化、三次连续 Native 请求 | 静态 system 与工具定义完全相同 |
| 真实变化 | 参考正文/来源、权限、工具集合、模式变化 | 请求及时变化，诊断解释首个变化 |
| 回放 | 重试、恢复、旧会话、队列插入、同时间戳输入 | 原前缀次序/内容保持，新提醒只注入一次 |
| 权限 | 保存不等于批准、plan 只读、历史伪造授权、goal evidence | 服务端状态和既有控制测试保持正确 |
| 压缩/预算 | 整步删除、提醒开销、最终超限、预览 | 无孤立 tool exchange，无无限保留 |
| Anthropic wire | 稳定 system、旧锚点、20+ 新块、已有标记、非法末尾 | 合法边界、总计不超过四个、不标 thinking |
| 元数据 wire | signature、encrypted reasoning、媒体、tool 配对 | 消息级/内容级选项和内容保持 |
| 路由 wire | auto/on/off、自定义连接、Chat/Responses | 不支持时无 Anthropic 缓存字段，store:false 不变 |
| 诊断 | 本地重复运行、分组、失败或缺失指标 | 不泄漏正文，不将本地稳定性冒充命中率 |

相关测试按原需求落入 llm-runtime、agent-runtime 及 synax 的现有测试文件，并新增 usage.test.ts 与 prompt-cache-wire.test.ts。执行相关 Vitest 与 `npm run typecheck`；必要时追加 web 类型检查以覆盖新增 API 字段。逐项标明通过、失败、未运行和已有问题，不使用宽泛的“测试通过”掩盖未测路径。

## 10. 实施顺序与交付

1. 固定当前工作区差异，记录相关测试/类型检查基线。
2. usage 归一化、边界证据和聚合兼容测试。
3. 确定性参考投影与请求级工具排序验证。
4. 静态/动态拆分、不可变提醒、回放/恢复/队列/压缩与预算测试。
5. 无损网关转换、明确能力开关、锚点预算及协议请求体测试。
6. 诊断脚本、使用说明、本地报告；条件允许时执行真实小样本。
7. 完整运行相关回归与类型检查，检查最终 diff 未覆盖无关工作。

最终交付包含实现代码、持久回归测试、`docs/integration/prompt-cache-diagnostics.md`、可重复脚本及报告。是否需要后续压缩高低水位、promptCacheKey 或 retention 优化只能基于实际数据提出建议，本批不自动更改。

## 11. 设计自审

- 无待定实现分支：采用分层增量方案；未知值、重试身份、锚点淘汰和失效路径均明确。
- 无语义冲突：稳定 system 不承载执行快照；完整请求预算包含提醒；缓存率匹配分子与分母。
- 范围受控：不重构外部 CLI/ACP 请求，不新增监控页面或请求正文存储，不改变压缩默认值。
- 风险保留：锁定 SDK/代理实际协议需 wire 测试；服务端缓存收益必须另行测量。
