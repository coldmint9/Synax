# 显式、流式的 Git 提交信息生成设计

- 日期：2026-09-21
- 范围：会话工作区的 Git 提交弹窗、专用生成接口、LLM 推理选项与相关测试。
- 目标：用户自行选择模型，主动触发流式生成，参考当前分支提交历史保持格式一致，确认或编辑消息后再提交。
- 非目标：自动提交、训练或持久化历史提交内容、让 ACP 模型参与此 LLM 网关调用、改变已有的 Git push 语义。

## 1. 现状与问题

现有 `SessionCommitDialog` 把空输入交给 `commitSessionWorkspace`，后者先 `git add -A`，再用会话模型调用 `generateGatewayTextResult`，最后直接提交。这使生成与有副作用的提交绑定，用户无法预览、修改生成结果或自行选模型。生成请求的 `maxTokens: 200` 对推理模型过小：实际调用的 200 个输出 token 几乎全部消耗在推理上，最终没有可用文本，界面只收到通用的 `GIT_COMMIT_MESSAGE_MISSING`。当前通用推理策略对 OpenAI-compatible 自定义推理模型的匹配也不完整。

## 2. 用户体验与状态

1. 提交信息输入框内放置 HeroUI `Button` 的 `isIconOnly` 星星按钮，使用项目已有的 `Sparkles` 图标。按钮有本地化的无障碍名称和提示，生成时显示等待状态，并允许取消。
2. 模型选择器只列出已配置、可由现有 LLM 网关调用的 API 模型；不混入 ACP 后端。首次默认当前会话模型；用户手动选择后，按项目记住选择。下次打开优先使用已记住且仍可用的模型，否则退回当前会话模型，再退回首个可用 API 模型。选择不会修改会话模型。
3. 点击星星后，用流式正文逐步替换输入框内容；不显示或写入隐藏推理。生成期间禁止手动编辑及提交，完成后可以自由修改。再次点击即重新生成并替换旧文本。如果失败、取消、关闭弹窗或切换仓库，恢复本次生成前的内容，忽略旧请求之后到达的片段。
4. 输入为空时，「仅提交」和「提交并推送」均不发送提交请求，而是提示先手写或生成；提交动作不会隐式调用模型。没有配置可用 API 模型时，星星按钮禁用，但仍可手写提交信息。

## 3. 服务端职责和数据流

新增会话级的 `POST /sessions/:sessionId/git/commit-message/stream`，请求体为可选 `rootId` 和**必需**的模型引用。复用现有会话、仓库根目录和活动运行校验；模型须由 LLM 网关按项目配置解析为可用 API 模型，不能仅凭前端选项信任传入的字符串。接口通过现有 Hono SSE / Gateway 流式能力输出文本增量、最终规范化消息及结束事件；错误以可读的流式错误事件传回，不记录密钥或完整 diff。客户端用 `AbortController` 取消请求；后端透传 abort signal，结束辅助用量记录和流资源。

提示词由以下只读数据构成：当前分支名称、Git 状态与已暂存/未暂存的文件名和受长度限制的 diff 摘要，以及**当前分支可见的最近 20 条非空提交 subject**。历史内容仅作为格式样本（语言、约定式前缀、scope、大小写和长度），不作为指令；分支无历史时退回简洁的通用提交格式。生成阶段不运行 `git add`、`commit` 或 `push`，对大 diff、二进制文件、未跟踪文件分别使用摘要或文件名并设定总输入上限，不把无界 Git 输出交给模型。

生成默认保持思考开启；请求提供适合短消息任务的推理档位和足够的输出上限（初始目标 4096 tokens），并让支持 `reasoning_effort` 的 OpenAI-compatible 自定义推理模型收到正确命名空间的选项。对不支持该选项的模型不注入陌生请求字段；对于无法关闭思考的 GLM-5.3 系列，绝不发送 `thinking.type: disabled`。用户只选模型，不需要在弹窗配置推理档位。服务端只转发可见文本 delta，完成后使用既有 `normalizeCommitMessage` 清洗为单行并发送最终消息；空输出是明确错误，而不是成功的空消息。

`commitSessionWorkspace` 保留原有根目录校验、暂存、提交和可选 push 行为，但移除其内部模型调用。后端也必须拒绝空消息（422），以约束直接调用 API 的客户端；更新现有路由 schema 和类型注释，核查其调用方对旧空消息语义的依赖。

## 4. 客户端结构

API 层为专用 SSE 请求提供带 `AbortSignal` 的方法和明确的 `delta`、`final`、`error` 事件类型，不能直接复用对话流的状态机。提交弹窗持有本次生成的原文快照、请求序号和控制器：选择会话/仓库变化或弹窗关闭时 abort 并使旧请求失效；即使取消和最后一个数据包竞争，旧请求也不能回写新表单。模型来源复用 composer 的 API 模型构造逻辑，模型偏好按项目持久化为小型键值；若缺少项目上下文，应从已有 session 元数据取得，而非把未知项目混写在同一个默认键。

星星按钮放在输入框内侧且不遮挡文本、滚动条或焦点环。生成出错时显示错误，保留可手动提交的路径。流式过程中以节流或按动画帧合并 UI 更新，避免每个字符触发一次大范围重渲染。

## 5. 错误、边界及安全

- 没有待提交变更、运行中的会话、无效仓库或不可用模型：在开始流前返回明确的验证错误；客户端保留原输入。
- 生成途中网络断开、模型错误、空输出或非正常结束：发出或抛出可读错误并恢复原文；不能把半截文本当成可提交消息。
- 用户主动取消、关闭弹窗、切换仓库或会话：立刻终止流并恢复生成前输入，不显示虚假失败提示。
- Git 记录可能包含任意文本：subject 和 diff 均作为不可信引用数据，按数量和大小限制；在提示词中明确其不能覆盖生成指令。
- 用户手写消息可绕过生成；服务端仍做原有长度清理和非空校验。生成与提交之间仓库可能继续变化，实际提交仍以提交时的当前状态为准，不在生成接口暂存或锁定工作区。

## 6. 验证与实施边界

先写失败用例，再做最小实现。服务端测试覆盖只读 Git 上下文、历史格式样本与空历史、选定模型和默认思考配置、流式增量/最终消息/空输出/取消、辅助用量收尾，以及提交接口空消息被拒绝、已有手写提交与 push 不受影响。客户端测试覆盖模型默认及按项目记忆、星星按钮可访问性、增量写入、重复生成替换、失败/取消恢复、仓库切换时丢弃迟到事件、空消息禁止提交。针对 OpenAI-compatible 推理模型增加 providerOptions 测试。最后运行相关 Vitest、API/Web TypeScript 检查及 Web 构建；可用时做不创建 Git 提交的本地流式验证。

预计涉及 `api/services/agent-runtime/session-git-commit.ts`（必要时拆出小型只读上下文/流服务）、`api/routes/agent-runtime.ts`、`api/services/llm-runtime/thinking-mode-strategy.ts`、`web/src/lib/api/agentRuntime.ts`、`SessionCommitDialog.tsx`、对应模型偏好和中英文本地化及测试。已有无关未提交修改保持原样；实施和测试不对真实工作区执行提交或推送。
