# 会话历史截断式回滚设计

状态：待实现
日期：2026-10-25

## 1. 目标

将会话回滚简化为“截断当前会话到某个历史节点”，而不是恢复旧的运行现场。用户可以在会话停止后选择：

- 仅截断会话记录；
- 截断会话记录并强制恢复工作区快照。

回滚必须保留目标节点及其之前的历史，删除目标节点之后的会话记录、快照引用和索引。压缩边界及之前的历史保持只读，不能回滚。

## 2. 明确规则

### 2.1 可回滚条件

服务端和客户端都遵守以下规则：

1. 会话及其子代理不得处于运行、排队、停止中、等待授权或等待输入状态。
2. 目标节点必须不是当前最新节点。
3. 目标节点必须位于最近一次上下文压缩边界之后。
4. 目标节点必须是可写的、非只读历史节点。
5. revision 必须与客户端预览时的 revision 一致；不一致时要求刷新历史。

“最新节点不能回滚”是业务规则，不依赖是否存在后续文件变更。

### 2.2 工作区快照

每轮会话结束后检查该轮造成的工作区状态：

- 有新增、修改或删除文件时创建一个完整工作区快照；
- 无文件变更时不创建重复快照，只复用最近的快照 ID；
- 快照必须能表达并恢复新增、修改、删除三类文件变化；
- 每个可回滚节点保存一个工作区快照引用，引用可以与前一节点相同；
- 节点之后被截断的快照引用从有效索引中删除。

快照不只保存 diff；它必须包含足够信息来恢复目标节点的完整工作区状态，包括删除后来新增的文件、恢复后来删除的文件以及还原修改文件。

### 2.3 工作区恢复语义

选择“包括工作区改动”时：

- 目标快照强制覆盖当前工作区；
- 当前工作区在快照之后被其他程序修改的内容不保留；
- 不做独立修改冲突检查；
- 不把外部修改写入新的历史记录；
- 恢复失败时不得提交会话截断，保证会话记录和工作区选择保持一致。

选择“仅回滚会话记录”时，工作区完全不变。

## 3. 后端架构

新增独立的 `truncate_history` 历史操作，替代回滚路径中的 `restore_checkpoint` 加逐实体收尾逻辑。

操作按以下顺序执行：

1. 加载会话历史头、压缩边界、目标节点和工作区快照引用。
2. 校验会话树为空闲状态。
3. 校验目标节点不是最新节点，且严格位于压缩边界之后。
4. 校验请求 revision 未过期。
5. 若包含工作区改动，准备目标快照恢复计划；恢复计划包含新增、修改、删除文件。
6. 在单个持久化提交中更新：
   - 当前历史根指向目标节点；
   - 当前有效 revision / history head；
   - 消除目标节点之后的消息、run、step、part、event、tool call、permission、interaction 和相关索引；
   - 消除目标节点之后的快照引用；
   - 清理覆盖被截断内容的上下文缓存和引用。
7. 若请求包含工作区改动，在同一恢复事务中应用目标快照。
8. 发布新的历史头和工作区状态，通知客户端刷新。

操作不修改压缩边界之前的任何实体，不遍历这些实体并尝试更新状态，也不恢复旧 run、step 或工具调用的执行状态。回滚后会话为 idle，下一条用户输入从目标节点继续。

底层 append-only 日志允许暂时保留被截断的物理记录；有效索引和历史根必须立即不可见。后续可通过独立垃圾回收压缩物理文件。

## 4. 会话删除与记录清理

删除会话时，不仅删除会话列表中的摘要，还必须清理该会话拥有或独占引用的全部记录：

- 会话历史消息、run、step、part、event、tool call、permission 和 interaction；
- 历史根、checkpoint、压缩摘要、上下文引用和历史索引；
- 该会话创建的工作区快照及快照索引；
- 该会话独占的附件、媒体和其他历史对象引用。

删除前先标记会话为 deleting，使它不再出现在可操作列表中，也不再接受新运行、历史读取、回滚或分叉请求。会话及其子会话必须处于非运行状态；若仍有活动执行，删除请求应拒绝并返回 `HISTORY_SESSION_BUSY`，不得静默删除正在运行的记录。

清理过程必须是幂等的，可在重启后继续。持久化提交应先移除会话的有效根和索引，再删除可安全删除的对象；共享对象只删除本会话的引用，不删除仍被其他会话引用的内容。清理完成后删除会话目录及空的快照、附件索引。若物理日志暂时不能立即重写，允许先完成逻辑删除并由后台垃圾回收回收孤儿对象，但任何历史 API、搜索、上下文读取和会话列表都不能再返回已删除会话的数据。

删除成功后：

- 会话 ID 返回 `NOT_FOUND`；
- 不能通过旧 checkpoint、message ID 或 object ID 恢复会话记录；
- 子会话和其专属记录按同一删除任务清理；
- 工作区本身不因删除会话而自动删除，除非该工作区是会话专属且删除接口明确选择了删除工作区。

## 5. 接口设计

保留现有历史预览接口，但返回：

- `canRollback`：综合最新节点、压缩边界和只读状态；
- `workspaceSnapshotId`：目标节点有效快照引用；
- `workspaceSnapshotChanged`：目标节点是否引用了不同于当前最新节点的快照；
- 不可回滚原因。

回滚请求增加显式模式：

```ts
type HistoryRollbackMode = "session" | "session_and_workspace";
```

请求至少包含：

```ts
{
  checkpointId: string;
  revision: number;
  requestId: string;
  mode: HistoryRollbackMode;
}
```

服务端错误保持可区分：

- `HISTORY_SESSION_BUSY`：会话或子代理仍在运行；
- `HISTORY_LATEST_NODE`：目标是最新节点；
- `READ_ONLY_HISTORY`：目标位于压缩边界或只读历史；
- `HISTORY_STALE`：历史已变化，需要刷新；
- `WORKSPACE_SNAPSHOT_NOT_FOUND`：目标节点快照不可用；
- `WORKSPACE_RESTORE_FAILED`：工作区恢复失败，未提交截断。

## 6. 前端交互

点击历史节点的回滚操作后打开模态框，而不是立即提交。

模态框包含两个单选项：

- 仅回滚会话记录（默认）；
- 回滚会话记录和工作区改动。

选择工作区模式时显示明确警告：

> 当前工作区将被目标节点的快照强制覆盖。目标快照之后由其他程序产生的新增、修改和删除不会保留。

确认按钮在请求执行期间禁用。成功后关闭模态框、刷新历史窗口、消息列表、工作区状态和快照引用。失败时保留模态框并显示服务端可读错误，不假设会话已回滚。

最新节点、压缩边界及之前节点不显示可用回滚操作；服务端仍执行同样校验，防止旧客户端绕过 UI。

## 7. 自动快照时机

在每轮会话结束的统一收尾路径中检查工作区状态：

1. 获取该轮开始时的工作区基线。
2. 获取会话结束时的工作区状态。
3. 比较新增、修改、删除文件。
4. 有变化则写入一个快照；无变化则复用当前最新快照引用。
5. 将快照 ID 写入该轮结束节点的元数据。

快照提交必须在会话轮次完成状态之后、历史节点对外可见之前完成；快照失败时不能产生一个声称可恢复但没有快照的节点，应记录明确失败状态并阻止“包括工作区改动”选项。

## 8. 测试验收标准

### 后端历史

- 空闲会话可以截断到压缩边界之后的非最新节点。
- 运行中、排队中、等待授权、等待输入的会话都被拒绝。
- 最新节点始终被拒绝。
- 压缩边界及之前节点始终被拒绝。
- revision 过期时不执行截断。
- 截断后消息、运行记录、工具记录和索引都只暴露目标节点之前的有效历史。
- 重启运行时后，截断结果仍然有效。
- 截断不修改压缩边界之前的对象。
- 不再因收尾写入封存实体而触发回滚失败。

### 工作区快照

- 新增文件可被恢复。
- 修改文件可被恢复。
- 删除文件可被恢复。
- 目标节点无文件变更时复用最近快照，不创建重复快照。
- “仅回滚会话记录”不修改工作区。
- “包括工作区改动”强制覆盖外部中途修改。
- 工作区恢复失败时会话截断不提交。

### 前端

- 点击回滚打开模态框。
- 默认选择仅回滚会话记录。
- 工作区模式显示覆盖警告。
- 最新节点和压缩边界节点不可操作。
- 成功后刷新会话、历史和工作区状态。
- 失败后保留一致的当前状态并显示错误。

### 会话删除

- 删除会话会清理其历史、索引、checkpoint、压缩摘要和专属快照引用。
- 删除进行中会话时被拒绝，不会留下半删除状态。
- 删除任务重启后可以继续，重复执行不会报错或破坏共享对象。
- 删除后历史读取、搜索、分叉和旧对象访问都返回 `NOT_FOUND` 或等价的不可用结果。
- 仍被其他会话引用的共享对象不会被误删。
- 删除会话默认不删除工作区。

## 9. 非目标

- 不恢复旧的模型执行、工具执行、授权请求或等待输入状态。
- 不创建新的会话分支。
- 不要求立即物理重写 append-only 历史文件。
- 不保留回滚目标节点之后由其他程序产生的工作区改动。
- 不允许回滚压缩前或压缩边界内的历史。
